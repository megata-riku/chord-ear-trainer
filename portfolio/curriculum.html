Curriculum and diatonic progressions

The default landing mode is step practice. Free practice remains available without unlock restrictions, including two- and three-chord progressions.

Stages 1–7: single chord with tonic/IV/V (3 choices); a target from all seven diatonic triads with 4 candidates; all 7 choices; two-chord sequence with 4 whole-sequence candidates; two-chord ordered input; three-chord sequence with 4 candidates; three-chord ordered input.

A challenge has ten first-answer records. Nine or ten wholly correct answers complete a stage. Order matters: a partially correct progression is one incorrect answer, with position correctness retained separately. In ordered input, users can select/edit a position, undo the last chord, then explicitly submit; incomplete sequences cannot be submitted. Partial selections and audio replay are not answer records.

Achievements are scoped by exact instrument/timbre ID and key. Duration and octave remain selectable. New practice never automatically plays the reference tonic. A manual-listening permission checkbox defaults on and is persisted and fixed for each session. Off hides/blocks the reference button. Review creates a fresh attempt under the current permission. Unlocks remain common but passed reference conditions are displayed. Pre-answer and post-answer usage are stored separately. A later failed attempt never revokes an achievement. Progress reconstructs from persisted unique answer records grouped by session ID. Only complete ten-answer challenges count. Free practice, incomplete sessions and manual history review do not unlock stages. Imported personal backups preserve IDs and achievements, including across browsers. This is not a multi-account or anti-cheat system.

Single-chord plans retain balanced coverage and maximum-two consecutive repeats. Ordered progression plans use ten unique targets: five common patterns and five other combinations. Four-choice generation uses policy progression-mixed-four-v3 (the record schema remains diatonic-progressions-v1 for backward compatibility). Each ten-question four-choice plan randomly interleaves exactly five balanced sets and five random sets. Balanced items first create four distinct diatonic candidate sequences with two chords per position, each occurring twice. Binary Cartesian masks for length 2 and even-parity masks for length 3 make all candidates have equal total overlap. Adjacent positions use disjoint pairs, excluding repeated adjacent chords in all candidates. Random items instead sample four distinct sequences uniformly without replacement from all diatonic progressions of the chosen length with no adjacent chord repetition; no column-count balancing is applied. Only after constructing and shuffling either type of set does an independent uniform draw choose the target (1/4 per displayed candidate). There is no post-draw rejection, target deduplication or common-pattern quota: these would bias that conditional probability. Common patterns seed some candidate sets but are not guaranteed to be the chosen answer. Ten targets need not be unique in four-choice sessions. Ordered input shows all seven chord buttons. Major examples include I→V, IV→I, ii→V→I, I→vi→IV and IV→V→I. Natural minor uses its actual diatonic triads (including a minor v), without harmonic-minor substitution. All 12 major and 12 natural minor keys are supported.

Each chord lasts the chosen duration plus any guitar strum span; silence between chords is 0.2 seconds. Legacy records with 0.1- or 0.35-second gaps remain valid and preserve their saved gap in history review and answer playback. Saved legacy questions with automatic reference playback retain their original 0.7-second reference gap on review. Progression answers become available after the complete target finishes playing, so answering cannot cut off the remaining chords. Stop/interruption cancels scheduled audio.

Records retain task: chord_progression, the key, input mode, generator version, ordered chord roots/qualities/actual MIDI notes/start times/durations/gap, all actual candidates, submitted sequence, per-position correctness, instrument, reference configuration, playback counts, response time and selection policy. The first chord's root/quality/notes remain on the question for compatibility, but must agree with the sequence. History replay uses saved notes and timings. Review restores the original question and records a new answer with sourceAttemptId and no curriculum credit. JSON validation checks chord identities, diatonic membership, timing, answer order, candidate legality and per-position correctness. Existing single-chord histories and achievements remain valid.

Feedback gives whole-sequence correctness, the correct and submitted sequences, a result for each position, replay of each actual target chord and selected chord, replay of the whole answer and the existing pitch-class comparison workspace for any position. The old redundant whole-target “play correct answer” button is not reintroduced.

The v3 prediction comparison supports single chords and full progression correctness. Five methods share chronological session holdouts; results are broken down by progression length, input format and candidate-generation mode. See prediction-experiment.md. Adaptive question selection is a later milestone.

Validation: node --test tests/*.test.cjs. Added tests cover 960 plans across 24 keys, unique targets/distractors, common-pattern quotas, piano/guitar/electric actual voicings, order-sensitive grading, position flags, corrupt backups, 8/10 versus 9/10, incomplete/review exclusion, unlock reconstruction and prediction eligibility. Browser QA covers both input styles, editing/undo, incomplete submission prevention, interruption/history, reference selection, and restored unlocks.

Update verification also covers balanced per-position counts and overlap in every generated candidate set, each of the four possible answers for an identical set, and removal of the automatic-reference setting.

The per-question progression.candidateMode records balanced or random; legacy histories omit it. Ordered-input plans are unchanged. Tests verify 5/5 quotas across all keys and lengths, random-set diversity, fixed-set answer selection, backup validation, and unlocks.
